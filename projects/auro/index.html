Robots that clean up after themselves.

A team of TurtleBot3 robots patrols a simulated arena, spots contaminated barrels with a camera, carries them to a drop-off zone, and goes off to decontaminate when its own radiation dose gets too high. No human in the loop.

The problem

The arena is scattered with red and blue barrels. Robots have to find them, pick them up with a rear holder, and deliver them to the right zone. Picking up barrels raises a robot's radiation level, and above a threshold it has to drive to a cyan decontamination zone before carrying on. Several robots share the arena, so they must not chase the same barrel or block each other, and everything runs against a clock.

How the controller works

Every robot runs its own robot_controller node, namespaced robot1, robot2 and so on. A finite state machine decides what the robot is doing at any moment. Small sub-phases inside some states (aligning, turning, reversing) keep each state simple.

StateWhat the robot does
SEARCHINGPatrols with Nav2 waypoints until the camera reports a barrel.
APPROACHINGChooses the best barrel and steers to it with proportional visual servoing, keeping it centred in the image.
POSITIONINGAligns, turns around and backs up so the rear holder lines up with the barrel.
PICKING_UPCalls the /pick_up_item service.
DELIVERINGNavigates with Nav2 to the drop-off zone.
OFFLOADINGCalls /offload_item.
CLEARING_SPACEMoves away from the zone so it doesn't block teammates, then checks its radiation dose.
DECONTAMINATINGDrives to the cyan zone, reverses in, and calls /decontaminate.

Engineering details

  • LiDAR sectoring

    The laser scan is split into front, left and right sectors. The closest reading in each drives obstacle avoidance while the robot is under direct velocity control.

  • Dynamic LiDAR mask

    While carrying a barrel, a mask is switched on through a parameter service so the robot doesn't treat its own cargo as an obstacle.

  • Multi-robot coordination

    Robots read shared /barrel_holders and /radiation_levels topics, so they skip barrels a teammate is already handling.

  • Data logging

    A separate data_logger node writes barrels collected and radiation levels to CSV every second, which is how runs were compared.

Testing

I ran five 3-hour scenarios with different random seeds and robot counts, logging every run to CSV. Detection accuracy stayed between 90 and 100% across them. The logs also showed where time was being lost, which led me to tune the decontamination threshold so robots didn't run out the clock on long sessions.

What I learned

State machines keep autonomy debuggable.

When a robot got stuck, the logged state told me exactly which behaviour was at fault, so fixes stayed local.

Mix planners with direct control.

Nav2 is great for crossing the arena, but the last half-metre to a barrel needed direct visual servoing to be reliable.

Measure before tuning.

Long logged runs, not one-off demos, showed which parameters actually mattered.
